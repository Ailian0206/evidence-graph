# 工作台职责区分与主张就地审核设计

修订日期：2026-07-27
状态：用户已确认

## 1. 目标

解决 C1 本地验收中暴露的三个问题：研究项目与研究报告入口职责不清、长主张列表的审核操作远离当前对象、全站品牌标记出现无产品含义的 `A/`。改动后，用户应能理解项目是持续研究过程、报告是项目产生的版本化产物，并能在当前主张处连续完成审核。

## 2. 已确认的产品关系

- 一个研究项目可以随着研究更新产生多版报告。
- 研究项目是研究问题、运行状态、来源、主张、证据和生命周期操作的容器。
- 报告是某次研究运行产生的版本化阅读产物，具有草稿、已发布或已撤销状态。
- 主张审核采用“当前主张卡片内就地操作”，不使用悬停专属控件、底部固定审核栏或独立审核抽屉。
- 接受或拒绝待审核主张后自动进入下一条待审核主张，并提供短时撤销入口。

## 3. 工作台信息架构

现有路由和数据库关系保持不变：

- `/{locale}/app` 继续作为研究项目列表。
- `/{locale}/app/reports` 继续作为当前用户的报告列表，导航和页面名称统一改为“报告库 / Report library”。
- `/{locale}/app/research/{projectId}` 继续作为研究工作台。
- `/r/{slug}` 继续作为无需登录的公开报告。

“研究项目”页面只表达研究过程：展示项目状态、研究问题、最近更新时间、语言、归档和删除，并保留“新建研究”。“报告库”页面只表达报告产物：移除“新建研究”主按钮，按项目分组。报告组按该项目最新报告的创建时间倒序排列，组内先按版本号、再按创建时间从新到旧展示每版报告。

每个报告版本显示版本号、报告状态、创建或发布时间和语言。草稿、已发布和已撤销版本都提供“查看报告”；该入口使用 `?view=report` 打开所属研究工作台并直接选中报告视图。已发布且具有 slug 的版本额外提供“打开公开报告”。报告组保留项目标题和研究问题，并提供次级“返回研究”入口，使版本产物与所属研究过程的关系明确但不混同。

报告列表为空时说明报告会在研究完成后生成，并提供返回“研究项目”的入口；不在报告库中直接创建项目。

## 4. 主张卡片结构

`WorkspaceClaimList` 继续负责列表和当前选择，但列表项不再由一个包住全部内容的 `<button>` 构成。每项改为语义化容器，内部包含：

- 一个覆盖主张摘要区域的选择按钮，维持键盘可达和 `aria-pressed` 语义。
- 仅在该项被选中时渲染的审核区域。
- 待审核主张显示“接受 / 拒绝”两个常驻按钮。
- 已接受或已拒绝主张显示当前状态和“恢复待审核”按钮。
- 当前请求进行中时禁用重复操作，并通过可访问状态文本说明正在保存。

审核按钮始终可见，不依赖 hover。移动端最小点击高度为 44px，长主张和双语按钮允许自然换行。原来位于完整列表之后的独立审核区删除，避免嵌套交互元素和重复控制。

## 5. 连续审核状态流

接受或拒绝一条待审核主张时按以下顺序执行：

1. 记录主张 ID 和原状态，乐观更新本地审核状态。
2. 从当前主张之后寻找下一条满足关系筛选条件的待审核主张；到达末尾后从顶部继续一次。
3. 找到时立即选中并使用 `scrollIntoView({ block: "nearest" })` 保持其审核按钮可见；不使用强制平滑滚动。
4. 未找到时停留在刚审核的主张，并显示“待审核主张已全部处理”。
5. 在新的视觉焦点处显示 6 秒的“上一条已接受/已拒绝 · 撤销”确认；下一次审核操作会替换该确认。

撤销调用同一审核契约，把上一条主张恢复为 `pending`，随后重新选中该主张。用户主动重新打开已接受或已拒绝主张时，也可以通过持久的“恢复待审核”入口完成同样操作。

审核状态筛选继续生效。若一次状态变化使当前主张不再属于所选筛选结果，界面优先选择下一条仍可见主张；没有可见项时显示现有空状态，不保留一个列表中不存在的选择。

## 6. 持久化失败与并发约束

Managed 工作台继续调用现有 `reviewClaim` Server Action，不修改数据库、RLS 或审核字段。一次审核请求未完成前禁用审核与撤销操作，避免同一客户端产生乱序更新。

持久化失败时必须：

- 把失败主张恢复到请求前状态。
- 重新选中失败主张并使其进入可见区域。
- 清除对应的成功/撤销确认。
- 在该主张审核区显示双语错误，并通过 `aria-live` 宣告。
- 保留按钮以便用户重试，不吞掉错误或静默跳到下一条。

Demo 工作台继续只更新本地状态，不发起持久化请求，但使用相同的自动前进与撤销交互。

## 7. 报告直达数据流

报告库不新增私有报告详情路由。报告入口把 `view=report` 作为显示意图传给研究详情页；页面验证该值，只向 `EvidenceWorkspace` 传递受限的初始模式 `graph | report`。当初始模式为 `report` 时，移动端同时把承载图谱/报告内容的 `graph` 面板设为活动标签，保证报告在窄屏首屏可见。工作台内部状态仍负责后续模式切换，未知查询值回退到 `graph`，并保持默认的主张移动端标签。

报告分组是展示层的纯映射，不改变 `ManagedReportSummary` 的数据库查询契约。分组键使用 `projectId`，项目标题和问题来自现有 owner-scoped PostgREST 查询；RLS 和 owner 条件继续决定可见范围。

## 8. 品牌标记

公共站点头部 `.brand-mark` 的可见文本由 `A/` 改为 `A`，保留现有圆形轮廓、`Ailian` 品牌名和 `Ailian home` 可访问名称。受管理工作台中的 `EG` 产品标记不变，因为它代表 Evidence Graph，而不是全站品牌。

## 9. 双语、可访问性与响应式约束

- 新增或修改的导航、状态、按钮、撤销和错误文案同时提供中文与英文。
- 选择主张、审核按钮和报告链接具有明确的可访问名称；状态变化使用克制的 live region，不抢占键盘焦点。
- 选中卡片展开审核区时，其他卡片尺寸可以变化，但页面与列表宽度不得变化。
- 桌面端保持现有三栏工作台；移动端审核区随选中主张出现在主张标签页内，不遮挡工作台标签或浏览器底部区域。
- 品牌、长主张、长项目标题和英文按钮在 390px 宽度下不得裁切或产生横向滚动。

## 10. 测试与验收

所有行为按 RED-GREEN 执行：

- Claim list 单测先覆盖选中卡片内的审核按钮，并确认列表底部不再存在重复审核区。
- Workspace 单测覆盖接受、拒绝、自动寻找下一条、末尾环回、全部处理完成、恢复待审核、短时撤销和 managed 失败回滚。
- 筛选测试覆盖状态变化后选择始终指向可见主张。
- Report dashboard 单测覆盖“报告库”文案、按项目分组、版本倒序、移除新建入口、报告视图直达和公开报告入口。
- Managed research page 单测覆盖 `view=report` 的合法值映射与未知值回退。
- Site header 单测覆盖可见品牌文本为 `A` 且不再出现 `A/`。
- 中英文 E2E 覆盖项目页、报告库和报告直达工作台。
- 在 390x844、1024x768、1440x1000 检查项目页、报告库和长主张审核，没有横向溢出、文字裁切、异常重叠或控件遮挡。
- 聚焦验证通过后运行 `npm run test:managed`；例行测试继续禁用真实 Provider。

## 11. 明确不做

- 不新增报告编辑器、报告搜索、筛选、分页、导出或跨用户报告目录。
- 不修改报告生成规则、数据库 Schema、migration、RLS、Provider 或部署配置。
- 不把项目列表与报告库合并成单页，也不删除报告库入口。
- 不实现批量接受/拒绝、键盘快捷键或悬停专属操作。
- 不修改 Evidence Graph 图谱、来源、日志和公开报告的内容结构。
- 不开始 C2-C6，不更新 `release`，不合并 Draft PR #18，直到当前 C1 验收问题修复、自动化门禁和用户复验完成。

## 12. 完成标准

用户能从导航和页面内容理解“研究项目是过程、报告库是版本产物”；能从报告库直接打开具体报告视图；无论主张数量多少，都能在当前主张卡片内完成连续审核、自动前进和撤销；保存失败可见且可恢复；全站头部只显示 `A` 品牌标记；三档视口和完整门禁通过。
